# Module Documentation: SSL / TLS Certificates, Let's Encrypt & Domain Verification

## 1. Overview
The SSL module provides full automated and custom TLS certificate lifecycle management for hosting domains on HPanel:
- Two-step domain verification: DNS Ownership proof via TXT record and routing validation via CNAME / Apex A/AAAA records.
- Automated Let's Encrypt certificates using Certbot over HTTP-01 ACME challenges through the Go agent's `ssl.issue` action.
- Modern Nginx TLS termination with HTTP/2 support and optional HSTS (`Strict-Transport-Security`).
- Custom commercial SSL certificate upload (PEM CRT + Private Key + Intermediate Chain) with cryptographic keypair matching.
- Automated daily renewal checks via scheduled console command `ssl:renew-expiring` for certificates expiring within 30 days.
- Automated 15-minute background DNS re-check via `domains:verify-pending` for pending domains (batch size up to 200).
- Webhook notifications on `ssl.issued` and `ssl.failed` events.

## 2. Domain Verification Architecture

Before SSL can be requested, customers must verify domain ownership and routing.

### 2.1 Configuration
Defined in `config/hpanel.php`:
- `edge_host`: The edge hostname (from `HPANEL_EDGE_HOST`, e.g. `edge.nexorafox.in`).
- `edge_fallback_ip`: Optional fallback IP (never used for DNS verification).
- `verification_txt_prefix`: DNS prefix for the TXT record, defaults to `_hpanel-verify`.

### 2.2 Ownership Proof (TXT)
- A random 32-hex `verification_token` is generated when the domain is created.
- The customer creates a DNS TXT record at `_hpanel-verify.<domain>`.
- The TXT value must strictly contain `hpanel-verify=<token>`.

### 2.3 Routing Check
- **Non-Apex domains**: The CNAME of the domain or its `www` subdomain must resolve to `edge_host` (normalized lowercase, ignoring trailing dots).
- **Apex domains**: CNAME cannot exist at the root DNS zone per RFC. Apex domains are verified by checking that their A and AAAA records match the dynamically resolved IPs of `edge_host` at check time.

### 2.4 Idempotent & Resilient Status Flow
- `pending_dns`: Initial state or unverified state.
- `verified`: Both ownership and routing checks pass.
- Transient DNS failures do **not** immediately downgrade a verified domain. The service tracks `dns_consecutive_failures` and only downgrades to `failed` after 3 consecutive check failures or upon explicit administrative action.
- When `verified`, the customer can request Let's Encrypt SSL.

## 3. HTTP-01 ACME Challenge Architecture

All virtual hosts generated by the Go agent automatically include a dedicated location block for ACME challenges:
```nginx
location ^~ /.well-known/acme-challenge/ {
    default_type "text/plain";
    root /var/www/letsencrypt;
}
```
### Key Benefits:
1. **Zero App Interference**: The `^~` prefix matches ACME requests immediately, preventing application front-controller rewrites (such as Laravel `index.php?$query_string` or WordPress `index.php?$args`) from intercepting challenge tokens.
2. **Accessible during Forced HTTPS**: When "Force HTTPS" is enabled, the port 80 block handles the challenge directly before redirecting regular web traffic to `https://$host$request_uri`.
3. **Shared Webroot**: Certbot writes challenge files to `/var/www/letsencrypt/.well-known/acme-challenge/`, which is instantly accessible to Let's Encrypt validation servers.

## 4. Go Agent Typed SSL Actions

| Action | Input Schema | Purpose |
|---|---|---|
| `ssl.issue` | `domain`, `email`, `alt_names[]`, `agree_tos` | Executes Certbot with webroot plugin; parses issued certificate into structured metadata (`cert_path`, `key_path`, `valid_to`, `days_remaining`). |
| `ssl.renew` | `domain`, `force` | Runs `certbot renew --cert-name <domain>` and returns updated certificate dates. |
| `ssl.revoke` | `domain`, `reason` | Runs `certbot revoke --cert-name <domain> --delete-after-revoke --non-interactive`. |
| `ssl.status` | `domain`, `cert_path` | Inspects certificate on disk and returns x509 details (issuer, subject, SANs, days remaining, expiry status). |
| `ssl.install_custom` | `domain`, `certificate`, `private_key`, `chain` | Cryptographically validates keypair with `tls.X509KeyPair`, writes key with `0600` permissions into `/etc/ssl/panel/<domain>/`, and stores certificate. |

All external commands are run strictly with argument arrays (`exec.Command("certbot", ...)`). Zero shell execution is permitted.

## 5. Modern TLS Nginx Configuration

When a certificate is active for a domain, the agent automatically configures the server block with hardened TLS settings:
```nginx
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name example.com www.example.com;

    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers off;

    # Optional HSTS Header
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
}
```

## 6. Automated Certificate Renewal & Scheduled Tasks

The scheduled commands run via the Laravel scheduler (`routes/console.php`):
```php
// Daily SSL renewal for expiring certificates (<= 30 days remaining)
Schedule::command('ssl:renew-expiring')->daily();

// Background DNS verification for pending domains (max 200 per run)
Schedule::command('domains:verify-pending --limit=200')->everyFifteenMinutes();
```
- `ssl:renew-expiring`: Queries active Let's Encrypt certificates where `auto_renew = true` and `valid_to <= now()->addDays(30)`. Dispatches `IssueSslCertificateJob` for each eligible domain.
- `domains:verify-pending`: Automatically re-checks pending domains in batches of 200 every 15 minutes, updating `verification_status`, `dns_last_checked_at`, and logging errors.

## 7. Failure Recovery

### DNS Verification Fails
1. Check the DNS helper UI on `/domains/{id}/dns` for the exact TXT record (`_hpanel-verify.<domain>`) and routing record required.
2. Ensure DNS propagation has completed across public resolvers using `dig TXT _hpanel-verify.<domain>` or `dig CNAME <domain>`.
3. For apex domains, confirm that your domain's DNS provider supports ALIAS/ANAME pointing to `edge_host`, or that direct A and AAAA records match the current edge IPs.

### ACME Challenge Fails (NXDOMAIN / Connection Refused)
1. Verify domain routing points to the server/edge IP.
2. Confirm port 80 is open in firewall (`ufw allow 80/tcp`).
3. If using Cloudflare proxy (Orange Cloud), ensure SSL mode is set to "Full" or "Full (Strict)".

### Private Key Mismatch
When uploading custom SSL certificates:
- Both the web UI and agent enforce keypair matching via OpenSSL / `tls.X509KeyPair`.
- Ensure the private key corresponds to the private key used to generate the Certificate Signing Request (CSR).
- Remove any passphrase protection from the private key before pasting.
