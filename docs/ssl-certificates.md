# Module Documentation: SSL / TLS Certificates & Let's Encrypt

## 1. Overview
The SSL module provides full automated and custom TLS certificate lifecycle management for hosting domains on HPanel:
- Automated Let's Encrypt certificates using Certbot over HTTP-01 ACME challenges.
- Modern Nginx TLS termination with HTTP/2 support and optional HSTS (`Strict-Transport-Security`).
- Custom commercial SSL certificate upload (PEM CRT + Private Key + Intermediate Chain) with cryptographic keypair matching.
- Automated daily renewal checks via scheduled console command `ssl:renew-expiring` for certificates expiring within 30 days.
- Webhook notifications on `ssl.issued` and `ssl.failed` events.

---

## 2. HTTP-01 ACME Challenge Architecture

All virtual hosts generated by the Go agent automatically include a dedicated location block for ACME challenges:
```nginx
location ^~ /.well-known/acme-challenge/ {
    default_type "text/plain";
    root /var/www/letsencrypt;
}
```
### Key Benefits:
1. **Zero App Interference**: The `^~` prefix matches ACME requests immediately, preventing application front-controller rewrites (such as Laravel `index.php?$query_string` or WordPress `index.php?$args`) from intercepting challenge tokens.
2. **Accessible during Forced HTTPS**: When "Force HTTPS" is enabled, the port 80 block handles the challenge directly before redirecting regular web traffic to `https://$host$request_uri`.
3. **Shared Webroot**: Certbot writes challenge files to `/var/www/letsencrypt/.well-known/acme-challenge/`, which is instantly accessible to Let's Encrypt validation servers.

## 3. Go Agent Typed SSL Actions

| Action | Input Schema | Purpose |
|---|---|---|
| `ssl.issue` | `domain`, `email`, `alt_names[]`, `agree_tos` | Executes Certbot with webroot plugin; parses issued certificate into structured metadata (`cert_path`, `key_path`, `valid_to`, `days_remaining`). |
| `ssl.renew` | `domain`, `force` | Runs `certbot renew --cert-name <domain>` and returns updated certificate dates. |
| `ssl.revoke` | `domain`, `reason` | Runs `certbot revoke --cert-name <domain> --delete-after-revoke --non-interactive`. |
| `ssl.status` | `domain`, `cert_path` | Inspects certificate on disk and returns x509 details (issuer, subject, SANs, days remaining, expiry status). |
| `ssl.install_custom` | `domain`, `certificate`, `private_key`, `chain` | Cryptographically validates keypair with `tls.X509KeyPair`, writes key with `0600` permissions into `/etc/ssl/panel/<domain>/`, and stores certificate. |

All external commands are run strictly with argument arrays (`exec.Command("certbot", ...)`). Zero shell execution is permitted.

## 4. Modern TLS Nginx Configuration

When a certificate is active for a domain, the agent automatically configures the server block with hardened TLS settings:
```nginx
server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name example.com www.example.com;

    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers off;

    # Optional HSTS Header
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
}
```

## 5. Automated Certificate Renewal & Scheduled Tasks

The scheduled command `ssl:renew-expiring` runs daily via the Laravel scheduler:
```php
Schedule::command('ssl:renew-expiring')->daily();
```
- Queries all active Let's Encrypt certificates where `auto_renew = true` and `valid_to <= now()->addDays(30)`.
- Enqueues `IssueSslCertificateJob` for each eligible domain.
- Upon successful renewal, re-dispatches `WriteVhostJob` to ensure Nginx reloads cleanly with the new certificate, and fires the `ssl.issued` webhook.

## 6. Failure Recovery

### ACME Challenge Fails (NXDOMAIN / Connection Refused)
1. Use the **DNS Records** helper (`/domains/{domain}/dns`) to ensure public DNS A records are pointing to the server's public IP.
2. Confirm port 80 is open in firewall (`ufw allow 80/tcp`).
3. If using Cloudflare proxy (Orange Cloud), ensure SSL mode is set to "Full" or "Full (Strict)".

### Private Key Mismatch
When uploading custom SSL certificates:
- Both the web UI and agent enforce keypair matching via OpenSSL / `tls.X509KeyPair`.
- Ensure the private key corresponds to the private key used to generate the Certificate Signing Request (CSR).
- Remove any passphrase protection from the private key before pasting.
